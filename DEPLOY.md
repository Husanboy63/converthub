# Размещение Convert в Proxmox

Инструкция для администратора. Приложение конвертирует изображения, отдаёт
готовые файлы и ZIP. Один Docker-контейнер содержит сервер Fastify и собранный
интерфейс Vue. Внешняя БД, Redis и Node.js на сервере не требуются.

## 1. Что передаёт разработчик

Готовый комплект `convert-admin-<версия>.tar.gz` содержит:

- `convert-image.tar.gz` — Docker-образ Linux/amd64;
- `docker-compose.yml` — запуск без сборки и скачивания образа;
- `.env.example` — настройки с точным тегом переданного образа;
- `DEPLOY.md` — эта инструкция;
- `IMAGE.txt` — идентификатор, архитектура и тег образа;
- `SHA256SUMS` — контрольные суммы файлов.

Архив формируется только после проверки контейнера: интерфейс, health check,
PNG → WebP/JPEG/PNG/AVIF, скачивание файлов и ZIP, сохранность задачи после
перезапуска. Это проверка базовой работоспособности, не нагрузочный тест.

Исходный архив `convert.tar` из старой рабочей папки не является этим образом.

## 2. Сервер

- Linux-виртуалка в Proxmox, архитектура x86_64/amd64.
- Docker Engine и Compose v2 с поддержкой `up --wait`.
- Ориентир: 2 vCPU, 4 ГБ RAM, 20–30 ГБ диска. В Compose контейнер ограничен
  2 CPU и 3 ГБ RAM, оставшаяся память нужна ОС. Настройки меняются в `.env`.
- Интернет для установки Docker и выпуска сертификата; само приложение
  после загрузки образа не требует скачивания пакетов для запуска.
- Временные файлы и метаданные задач хранятся в `./data` на виртуалке.

Docker устанавливает администратор по стандартам инфраструктуры.
Официальная инструкция: https://docs.docker.com/engine/install/debian/
Для Docker команда Proxmox рекомендует отдельную виртуалку:
https://forum.proxmox.com/threads/how-to-use-docker-containers-in-proxmox.131142/

Далее команды выполняются в Linux из учётной записи с правами на Docker.

## 3. Первый запуск

Скопируйте полученный архив на виртуалку. Вместо `<версия>` подставьте имя
переданного релиза. Каталог `/opt/convert` должен быть выделен этому приложению.

```bash
sudo mkdir -p /opt/convert
sudo chown "$(id -u):$(id -g)" /opt/convert
tar -xzf convert-admin-<версия>.tar.gz -C /opt/convert
cd /opt/convert
sha256sum -c SHA256SUMS
docker load -i convert-image.tar.gz
cp .env.example .env
sudo install -d -o 1000 -g 1000 -m 0750 /opt/convert/data
```

Контейнер работает от UID/GID `1000:1000`, поэтому папка `data` должна быть
доступна этому пользователю для записи. Если папка уже содержит данные,
проверьте владельца вложенных файлов перед повторным использованием.

Отредактируйте `.env`:

| Настройка | Значение/назначение |
| --- | --- |
| `CONVERT_IMAGE` | Точный тег из комплекта; при первом запуске оставить как есть |
| `BIND_ADDRESS` | По умолчанию `127.0.0.1`; для прокси в другом LXC/VM указать внутренний IP этой виртуалки |
| `HTTP_PORT` | Порт виртуалки, по умолчанию `3000` |
| `MAX_FILE_SIZE_MB` | Максимум на файл, по умолчанию `50` МиБ |
| `MAX_FILES_PER_JOB` | Максимум файлов в загрузке, по умолчанию `50` |
| `QUEUE_CONCURRENCY` | Одновременно обрабатываемые файлы, по умолчанию `2` |
| `FILE_TTL_HOURS` | Срок временного хранения, по умолчанию `2` часа |
| `RATE_LIMIT_PER_MIN` | Запросы в минуту, включая опрос статуса, по умолчанию `600` |
| `CPU_LIMIT` / `MEMORY_LIMIT` | Лимиты контейнера, по умолчанию `2.0` / `3g` |

```bash
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90
docker compose ps
docker compose logs --tail=100
```

Проверьте `http://<BIND_ADDRESS>:<HTTP_PORT>/api/health`; ожидается JSON
с `"status":"ok"`. Например, для настроек по умолчанию:

```bash
curl --fail http://127.0.0.1:3000/api/health
```

Если выбран внутренний IP, замените `127.0.0.1` в этой команде на него.
Откройте `/` в браузере, загрузите тестовое изображение, скачайте файл и ZIP.
При локальной привязке используйте SSH-туннель или сразу настройте прокси.

## 4. Домен, Nginx Proxy Manager и HTTPS

Возможная схема: интернет → Nginx Proxy Manager → внутренний IP виртуалки:3000.
Для прокси в отдельном LXC/VM адрес `127.0.0.1` указывает на сам прокси,
поэтому в `.env` приложения нужен внутренний IP виртуалки с Convert.

1. Создайте DNS-запись поддомена, например `convert.company.ru`, направленную
   на внешний адрес входного прокси. Настройте маршрутизацию/NAT портов 80/443,
   если они ещё не настроены в инфраструктуре.
2. В Nginx Proxy Manager создайте Proxy Host: доменное имя, схема `http`,
   Forward Hostname/IP — внутренний IP виртуалки, Forward Port — `3000`.
3. Выпустите или подключите сертификат для домена, включите Force SSL.
4. В Advanced настройте лимит тела запроса и таймауты. Для штатного максимума
   50 файлов по 50 МиБ пример ниже допускает всю пачку с небольшим запасом.
   При меньших лимитах приложения уменьшите значение соответственно.

```nginx
client_max_body_size 2600m;
client_body_timeout 300s;
proxy_read_timeout 300s;
proxy_send_timeout 300s;
```

Большая загрузка может также временно занимать диск самого прокси.
Проверьте загрузку и скачивание через итоговый HTTPS-адрес.
Доступ к порту приложения разрешите от прокси; наружу обычно достаточно
публиковать HTTPS. Учитывайте, что опубликованные Docker-порты требуют
правил фильтрации, совместимых с Docker, а не только обычных правил UFW.

В приложении нет пользователей и паролей. Без ограничений на прокси сервис
доступен всем посетителям домена. Если доступ нужен только сотрудникам через
интернет, используйте принятую в компании авторизацию на прокси.

Текущая версия не доверяет `X-Forwarded-For`: за одним прокси лимит запросов
общий для клиентов этого прокси. При 429 учитывайте частый опрос статуса
интерфейсом; настройте общий лимит и при необходимости ограничения на прокси.

## 5. Обслуживание

```bash
cd /opt/convert
docker compose ps
docker compose logs --tail=200 -f
docker compose restart
# Остановить сервис без удаления данных:
docker compose down
# Возобновить:
docker compose up -d --wait --wait-timeout 90
```

`restart: unless-stopped` обеспечивает запуск при перезапуске Docker/ОС,
если контейнер ранее не был остановлен вручную. Состояние `unhealthy`
само по себе не перезапускает живой процесс: проверяйте логи.
Перед обновлением дождитесь завершения текущих конвертаций. Серверу даётся
до 35 секунд на остановку; длинные операции могут быть прерваны.

Очистка запускается каждый час. Файлы удаляются после истечения TTL,
поэтому фактическое хранение может быть примерно на час дольше указанного.
Следите за свободным местом и загрузкой RAM. Это временное хранилище,
а не архив изображений; резервные копии данных — по политике компании.
Сохраняйте конфигурацию и прошлые образы для восстановления.

## 6. Обновление и откат

Распакуйте новый комплект в отдельную папку, например `/opt/convert-release-new`.
В ней выполните `sha256sum -c SHA256SUMS` и `docker load -i convert-image.tar.gz`.
Сохраните старый комплект и текущие `.env`/`docker-compose.yml`.
Сравните новый Compose и пример настроек с рабочими: при необходимости
обновите Compose и добавьте новые параметры, сохранив рабочую папку `data`.
В `/opt/convert/.env` измените только тег `CONVERT_IMAGE` на тег нового релиза
и выполните из `/opt/convert`:

```bash
docker compose up -d --wait --wait-timeout 90
docker compose ps
```

Для отката верните предыдущий тег и совместимые с ним настройки/Compose,
затем повторите команду. Если старый образ удалён, загрузите его из сохранённого
архива. Текущие данные остаются в `/opt/convert/data`.

## 7. Получение комплекта из исходников

После загрузки кода на GitHub workflow `Build admin Docker bundle` запускается
для ветки `main` и вручную через Actions → Run workflow. После успешной сборки
скачайте artifact `convert-admin-<commit>`, распакуйте внешнюю ZIP-обёртку GitHub
и передайте админу находящийся внутри `convert-admin-<версия>.tar.gz`.
Artifact хранится 14 дней. Registry и учётные данные GitHub на проде не нужны.
Доступность запуска зависит от разрешений и квоты Actions вашего аккаунта.

Локальная альтернатива на Linux с Docker, Compose v2, Node.js 22+ и GNU tar:

```bash
bash scripts/build-release.sh 1.0.0
```

Результат: `release/convert-admin-1.0.0.tar.gz`. Повторно используйте новый
номер версии. Целевая архитектура — amd64; для ARM нужен отдельный образ.
Скрипт оставляет небольшие тестовые данные в `/tmp/convert-smoke-*` для диагностики.
